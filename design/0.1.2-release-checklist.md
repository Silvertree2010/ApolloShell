# Releasing 0.1.2

What is done, what is left, and the order it has to happen in. Everything
here that touches GitHub needs a person - none of it runs on its own.

## Done in the repository

- Automatic updates for the `.dmg` build (Sparkle 2.10.0), the Nexus page,
  the Homebrew marker, and the tag-only release workflow.
- Themes applied across the shell, with gradients in the format and a Nexus
  page to pick, import and inspect them.
- The dock and launcher menus mirror the menu Apple's Dock shows for an app.
- `CFBundleShortVersionString` is `0.1.2`; the CHANGELOG section is
  `[Unreleased] - 0.1.2` and becomes `[0.1.2] - <date>` on the release day.

## Done as well

- **The signing keys exist.** `scripts/make-release-keys.sh` created the
  certificate `ApolloShell Release Signing` in the login keychain and an
  EdDSA key pair; the public key is in `Support/Info.plist`. Both private
  keys and the certificate password are in
  `~/Downloads/apolloshell-release-keys/`.
- **The four secrets are set** on `Silvertree2010/ApolloShell`:
  `RELEASE_CERT_P12`, `RELEASE_CERT_PASSWORD`, `SPARKLE_EDDSA_KEY` and
  `TAP_DEPLOY_KEY`. The tap is written with a deploy key that only works for
  `Silvertree2010/homebrew-apolloshell`, not with an account-wide token.

**Back the keys up somewhere that is not GitHub.** If the EdDSA key is lost,
no installed copy can ever update itself again - Sparkle only allows a key
change when the Apple signature matches, and an own certificate is not one.

## Left to do, in this order

1. **Try the shell once, by hand**, before tagging anything. The interface
   has not been seen running: themes, the Nexus pages and the mirrored dock
   menu are only covered by tests and by the compiler so far.

   ```sh
   ./build.sh   # careful: overwrites ~/Applications/ApolloShell.app,
                # which is currently a symlink into the Homebrew Cellar
   ```

   Check: a theme applies and reloads on save; Nexus > Updates shows the
   Homebrew hint; a right click on a dock icon shows that app's own menu;
   the log says what the mirror saw:

   ```sh
   log show --predicate 'subsystem == "io.github.silvertree2010.apolloshell" AND category == "dockmenu"' --last 5m
   ```

2. **Set the CHANGELOG date** and push the branch.

3. **Tag and let the workflow run:**

   ```sh
   git tag -a v0.1.2 -m "ApolloShell 0.1.2"
   git push origin v0.1.2
   ```

   The workflow refuses to run if the tag does not match
   `CFBundleShortVersionString` or if `SUPublicEDKey` is empty. It builds the
   universal DMG, signs it with the release certificate and the EdDSA key,
   generates `appcast.xml`, publishes the release and updates the tap.

4. **After the release**, confirm the update path end to end: install 0.1.2
   from the DMG, publish a test 0.1.3, and watch a real update install
   itself - including whether the Accessibility grant survives it. That is
   the one promise of this release that no test can make.
